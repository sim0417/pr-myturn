# pr-myturn

내 PR 현황을 읽어 **지금 내가 해야 할 일**을 알려준다.

## 데이터를 어디서 읽나

두 갈래가 있다. **먼저 캐시를 본다.**

```sh
cat ~/.cache/pr-myturn/status.json
```

메뉴바 앱이 5분마다 갱신하므로 대개 이걸로 충분하고, GitHub 을 부르지 않아 즉시 답할 수 있다.
`generatedAt` 을 보고 너무 오래됐거나(10분 이상) 파일이 없으면 직접 수집한다.

```sh
~/.cache/pr-myturn/../../projects/pr-myturn/bin/pr-status.sh --md
```

경로가 확실하지 않으면 `pr-status.sh --md` 를 PATH 에서 찾거나 레포 위치를 사용자에게 묻는다.
`--md` 는 마크다운, `--json` 은 구조화된 데이터를 준다.

## 분류를 그대로 믿어라

각 PR 에는 `bucket` 과 `reason` 이 이미 붙어 있다. **직접 판정하지 마라.**
승인 개수를 세거나 코멘트를 해석해 재분류하면 도구의 판정과 어긋난다.

| bucket | 뜻 | 사용자에게 할 말 |
|---|---|---|
| `action` | 내 차례 | 지금 해야 할 일. `reason` 을 그대로 전한다 |
| `merge` | 승인 완료, 막힌 것 없음 | 머지하면 된다 |
| `waiting` | 아직 승인 전 | 상대 차례. 오래 묵었으면 리마인드를 제안한다 |

`reason` 은 `변경 요청` / `충돌 해결` / `브랜치 업데이트` / `답변 필요` / `미해결 스레드` 중 하나다.

## 어떻게 답하나

- **`action` 부터 말한다.** 그게 사용자가 알고 싶은 것이다.
- 건수만 나열하지 말고 **무엇을 해야 하는지** 말한다. "1건 있습니다" 보다
  "classic-backoffice#1677 에 변경 요청이 있습니다. HyukjoonLee 가 P1 로 지적한 게 미해결입니다" 가 낫다.
- `action` 이 비어 있으면 그 사실을 먼저 말한다. 이어서 `merge` 를 짚는다.
- URL 은 그대로 준다. 사용자가 바로 누른다.
- 오래 묵은 `waiting` 은 대기 일수를 함께 말한다. `created` 로 계산한다.

## 하지 말 것

- 상태를 바꾸지 마라. 머지, 코멘트 작성, 리뷰 요청은 사용자가 명시적으로 시킬 때만 한다.
- `status.json` 을 고치지 마라. 도구가 덮어쓴다.
- 캐시가 최신인데 GitHub 을 다시 부르지 마라. 느려지기만 한다.
